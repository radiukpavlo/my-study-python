# 3. Налаштування інструментів

**Статус:** Draft
**Дата:** 21 квітня 2026

Цей розділ описує, як встановити, сконфігурувати і перевірити AI-середовище розробки так, щоб воно було готове до реальних задач. Це не перелік посилань на офіційні інструкції — це нормативний setup-guide: що саме увімкнути, що вимкнути, як документувати обраний toolset у проєкті та як перевірити, що все працює.

Базова теза розділу: **setup — це engineering task, а не "поставив і забув".** Якщо privacy mode не увімкнено, якщо немає `AGENTS.md`/`CLAUDE.md`, якщо модель не зафіксована — інструмент технічно встановлений, але робота з ним не відповідає стандартам компанії. Setup вважається завершеним лише після проходження verification checklist наприкінці розділу.

## Що читач має винести з цього розділу

Після прочитання інженер повинен:

- мати встановлений і авторизований primary tool, обраний у розділі 2;
- мати увімкнені privacy/no-train settings на всіх cloud-інструментах, що використовуються на клієнтському коді;
- мати базовий `AGENTS.md` або `CLAUDE.md` у корені проєкту з описом стеку, команд і conventions;
- мати налаштований model routing (default → Sonnet, складне → Opus) у primary tool;
- мати хоча б один MCP-сервер, релевантний проєкту (Jira/GitHub/Figma або framework-specific);
- знати, як перевірити коректність setup на starter-задачі;
- знати, як задокументувати setup у проєктній документації для наступного інженера.

## Передумови

Перед тим, як ставити AI-інструменти, інженер має підтвердити базові передумови. Пропуск цього кроку — причина більшості setup-проблем.

### Project-level

- У контракті / NDA перевірено, чи дозволено використання AI на коді клієнта. Якщо заборонено або не обговорено — зупинись, узгодь із PM або Security officer.
- Якщо клієнт має approved tool list — фіналізуй primary tool тільки з цього списку.
- Визначено, чи код можна надсилати до cloud AI, чи потрібна локальна модель (sensitive zone).
- Є доступ до реального проєктного репозиторію — setup перевіряється на справжньому коді, не на playground.

### Engineer-level

- Актуальна версія OS (macOS 14+, Windows 11, Ubuntu 22.04+) — на старіших системах частина нових версій AI-tool'ів не встановлюється.
- Node.js LTS (не нижче 20.x) — потрібен для Claude Code CLI та багатьох MCP-серверів.
- Git налаштовано, SSH-ключі додано до GitHub / GitLab / Bitbucket, що використовуються на проєкті.
- Робочий email (корпоративний або проєктний — згідно з політикою проєкту) для авторизації у підписках.
- Менеджер паролів / secrets manager — API-ключі не зберігаються у plain text.

> 💡 **Hint:** Setup робиться на робочій машині у робочий час, не на особистій. Якщо client-policy вимагає corporate laptop — усі AI-tools і підписки мають бути прив'язані до corporate identity, не особистого Google-акаунту. Міксовані setup-и створюють compliance-ризики і болючі міграції.

## Встановлення primary tool

Усі чотири primary tools із розділу 2 встановлюються за власними процедурами, але конфігуровані далі за єдиним каркасом: privacy → model routing → context file → verification.

### Cursor

AI-native IDE на базі VS Code.

**Кроки встановлення:**

1. Завантажити installer з `cursor.com/downloads` для своєї OS.
2. Встановити та запустити. При першому запуску — sign in через робочий Google/GitHub account.
3. Якщо раніше працював у VS Code: при першому запуску Cursor пропонує імпорт settings, extensions, keybindings — прийняти.
4. Перевірити version: `Cursor → About` має показувати актуальну stable version (update at least monthly).

**Обов'язкові settings (Cmd/Ctrl+,):**


| Setting                                          | Значення           | Причина                                                       |
| ------------------------------------------------ | ------------------ | ------------------------------------------------------------- |
| Privacy Mode (Settings → General → Privacy)      | Enabled            | Код не використовується для тренування моделей                |
| Sharing for improvement                          | Disabled           | Дубльований вимикач для telemetry; на клієнтських проєктах обов'язково |
| Auto-update                                      | Enabled            | Швидкий цикл фіч; не пропускати                               |
| Files.autoSave                                   | `afterDelay` (1s)  | Агентні правки не губляться через забутий ⌘S                  |

**Встановлення CLI для скриптів:**

```bash
cursor --install-extension <id>
```

CLI доступний після вибору `Cmd+Shift+P → Shell Command: Install 'cursor' command in PATH`.

### Claude Code

Terminal-native AI agent від Anthropic.

**Кроки встановлення:**

1. Переконатися, що встановлено Node.js 20+: `node --version`.
2. Встановити CLI глобально:

```bash
npm install -g @anthropic-ai/claude-code
```

3. Запустити у корені будь-якого проєкту: `claude`.
4. При першому запуску — OAuth-авторизація через браузер (Anthropic Pro / Max / Team акаунт).
5. Перевірити: `claude --version` має повернути поточну версію без помилок.

**Обов'язкові settings:**

- `~/.claude/settings.json` → `"env"` — вимкнути збір даних (на client-проєктах):

  ```json
  "env": {
    "DISABLE_ERROR_REPORTING": "1",
    "DISABLE_BUG_COMMAND": "1"
  }
  ```

  > Взагалі-то вся лишня телеметрія вимикається флагом `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` , але Станом на 23 квітня 2026 є [баг](https://github.com/anthropics/claude-code/issues/34178), через який виставлення цього флага (а також `DISABLE_TELEMETRY`) робить так, що зникає доступ до Opus з 1M-контексту та деяких інших фіч. Тому поки що рекомендується використовувати флаги вище, а не ці два. Коли баг буде пофікшено — має бути достатньо одного `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`.

  > Актуальний source of truth: [Data usage — Claude Code Docs](https://code.claude.com/docs/en/data-usage).

- `~/.claude/settings.json` → `"model": "opusplan"` — Opus для планування, Sonnet для виконання. Оптимальний баланс якості та швидкості (перемикання per-session: `/model sonnet`, `/model opus`).
- Працює поряд із будь-якою IDE. Для WebStorm / IntelliJ є офіційний плагін (Marketplace → "Claude Code") — ставиться окремо, працює як thin wrapper над CLI.

> 💡 **Hint:** Не запускай Claude Code з `$HOME` як поточної директорії. Агент індексує cwd і отримує доступ до файлів поза проєктом — це і privacy-ризик, і джерело hallucinations. Завжди `cd <project-root>` перед `claude`.

### GitHub Copilot

AI plugin від Microsoft / OpenAI.

**Кроки встановлення (VS Code):**

1. Marketplace → встановити `GitHub Copilot` та `GitHub Copilot Chat`.
2. Sign in через GitHub account (корпоративний, якщо проєкт використовує client-provisioned ліцензію).
3. Перевірити status: іконка Copilot внизу IDE — має бути "Ready".

**Кроки встановлення (JetBrains):**

1. `Preferences → Plugins` → встановити `GitHub Copilot`.
2. Restart IDE → `Tools → GitHub Copilot → Login`.

**Обов'язкові settings:**

> 💡 **Увага:** `Suggestions matching public code` встановлюється на **github.com → Settings → Copilot → Policies**, не в IDE. `Agent mode` — тільки VS Code; у JetBrains plugin недоступний.

| Setting                                           | Платформа       | Значення     | Причина                                                   |
| ------------------------------------------------- | --------------- | ------------ | --------------------------------------------------------- |
| Suggestions matching public code                  | github.com      | Block        | Знижує ризик ліцензійного забруднення                     |
| Telemetry / usage data                            | IDE settings    | Disabled     | Обов'язково на client-проєктах                            |
| Agent mode (Copilot Chat)                         | VS Code only    | Enabled      | Потрібне для multi-file задач у Copilot workflow          |
| Model selection                                   | Chat panel (UI) | Claude / GPT-5.x / Gemini залежно від задачі | Multi-model routing доступний у Pro+ та Business          |

### JetBrains AI Assistant

Нативний AI в IntelliJ / WebStorm / PyCharm / RubyMine.

**Кроки встановлення:**

1. `Preferences → Plugins` → встановити `AI Assistant`.
2. `Tools → AI Assistant → Log in` — авторизуватися через JetBrains Account з активною AI-підпискою (або Ultimate, що включає AI-tier).
3. Перевірити model list: `Settings → Tools → AI Assistant → Models` — обрати Claude Sonnet / Opus як default.

**Обов'язкові settings:**


| Setting                                       | Значення     | Причина                                             |
| --------------------------------------------- | ------------ | --------------------------------------------------- |
| "Share data for product improvement"          | Disabled     | Код не йде на тренування                            |
| "Detect secrets in input"                     | Enabled      | Автоматичний фільтр API-ключів перед відправкою     |
| "Disabled completion for" (file patterns)     | Налаштувати  | Додати `.env*`, `secrets/*`, client-sensitive директорії |

> 💡 **Hint:** Якщо інженер уже має JetBrains Ultimate — AI-токени входять у підписку і включають доступ до Claude / GPT / Gemini через один account. Окрема підписка на Claude Code / Copilot у цьому випадку часто надлишкова; спочатку вичерпай ліміт JetBrains AI, потім оцінюй доплату.

## Приватність і безпека

Ці settings застосовуються **на всіх AI-tools без виключень**, якщо код хоча б теоретично може бути client code.

### Дата-шарінг

- Privacy mode / "do not train" — enabled на рівні tool.
- Telemetry / analytics sharing — disabled.
- Для Cursor: `Settings → Privacy → Privacy Mode`.
- Для Claude Code: див. [налаштування вище](#claude-code).
- Для Copilot: `Settings → GitHub Copilot → Suggestions matching public code: Block`, `Allow GitHub to use my data: Off`.
- Для JetBrains AI: `Settings → Tools → AI Assistant → Data Sharing: Off`.

### Credentials hygiene

- `.env`, `.env.local`, `secrets/`, `*.pem`, `*.key`, `credentials.json` — додати у `.cursorignore` / `.aiignore` / tool-specific ignore файл.
- У репозиторії — `.gitignore` уже закриває ці файли; AI-ignore — окрема зона, бо AI бачить файли локально незалежно від git.
- API-ключі для самих AI-tool'ів (коли використовується API-білінг) — у OS keychain / 1Password / Bitwarden, не в plain config files.
- Для API-based setup у CI/CD — через GitHub Actions secrets / GitLab CI variables, ніколи не hardcoded.

### Sensitive zones

Якщо на проєкті є директорії з особливо чутливим кодом (billing logic, auth, crypto, client PII):

- Додати pattern у AI-ignore файл.
- На таких зонах — local model (Ollama / LM Studio) замість cloud.
- У `AGENTS.md` / `CLAUDE.md` зафіксувати: "AI заборонено на `src/billing/**`".

Приклад `.cursorignore`:

```
.env*
secrets/
*.pem
*.key
credentials*.json
src/auth/crypto/
```

## Налаштування моделей

Якщо primary tool multi-model (Cursor, Copilot Pro+, JetBrains AI, Claude Code з API-доступом) — закріпити дефолт і короткий routing per tool.

### Default model

- Default — **Claude Sonnet 4.6** для 90% задач (узгоджено з розділом 2).
- Opus — **вручну** на задачі, де це явно виправдано (архітектура, multi-file refactor, складний debug).
- GPT Codex / GPT-5.x — як **independent reviewer** або для швидкого boilerplate.
- Gemini Pro — для задач з контекстом > 100k токенів.

### Як зафіксувати

**Cursor:**

- `Settings → Models` → увімкнути лише моделі, що реально використовуються. Зайві вимкнути, щоб не натискати випадково дорогу модель.
- У `Cmd+L` (chat) — обрати Sonnet як default для нових chat-ів.

**Claude Code:**

- Див. [`"model": "opusplan"` у налаштуваннях Claude Code](#claude-code). Перемкнутись на сесію: `/model opus` або `/model sonnet`.

**Copilot:**

- У chat — перемикач моделі в правому нижньому куті. Встановити Claude Sonnet як pinned.

**JetBrains AI:**

- `Settings → Tools → AI Assistant → Models → Default`.

> 💡 **Hint:** Перемикання моделей "на льоту" без причини — токени, зливані в нікуди. Фіксуй модель на початку сесії під тип задачі і не перемикай до кінця задачі. Якщо потрібен verifier — це окрема сесія, не той самий chat.

## Entry-point: AGENTS.md / CLAUDE.md

Без entry-point файлу AI не знає, що за проєкт, які команди, які conventions. Setup primary-tool без entry-point — неповний.

### Що це

- **AGENTS.md** — універсальний формат, читають Cursor, Copilot (через `.github/copilot-instructions.md` як fallback), Codex, інші tools.
- **CLAUDE.md** — нативний формат Claude Code.
- На проєкті тримай обидва як **symlink** один на одного або як два файли з однаковим змістом. Тоді будь-який tool знайде свій.

### Мінімальна структура

Файл кладеться у корінь репозиторію. Мінімум, що має бути:

```markdown
# <Project Name>

Коротко: тип проєкту, стек, головне призначення.

## Quick reference

Основні команди — install, dev, build, test, lint.

## Architecture overview

1-2 абзаци: як фізично організовано проєкт (моноліт / монорепо / мікросервіси), які ключові директорії, entry point.

## File naming conventions

Таблиця: artifact → pattern → example. Саме цих конвенцій AI має дотримуватися.

## Before implementing anything

- Прочитай вже існуючий код у модулі.
- Шукай reusable код перед створенням нового.
- Слідуй існуючим patterns, не вводь нові без узгодження.

## Code style rules

Явні правила: що обов'язково, що заборонено (no `any`, OnPush, Maybe<T>, import order тощо).

## Testing

Де лежать тести, яким тулом запускаються, coverage-target, які файли обов'язково мають тест.

## AI-setup notes

- Primary tool: <Cursor / Claude Code / Copilot / JetBrains AI>
- Default model: Claude Sonnet 4.6
- Sensitive directories (AI заборонено): <список>
- Approved MCP servers: <список>
```

### Як заповнити швидко

1. Скопіюй `package.json` / `pom.xml` / `*.csproj` у діалог з AI і попроси згенерувати першу версію `AGENTS.md` із секціями вище.
2. Перечитай рядок за рядком — AI не знає internal naming (ULID, `I`-prefix для interfaces, kebab-case для файлів). Ручне доповнення обов'язкове.
3. Додай секцію `AI-setup notes` — це робить setup self-documenting для наступного інженера.
4. Commit у репозиторій (не в `.gitignore`).

### Глибша ієрархія

Для монорепо з різними стеками — окремі `AGENTS.md` на рівні кожного app/lib. Кореневий файл містить links: `See @apps/web/AGENTS.md for Angular conventions.`

> 💡 **Hint:** Якщо на проєкті ще немає AGENTS.md/CLAUDE.md — створення цього файлу має бути твоєю першою AI-задачею на проєкті, а не "зроблю потім". Без нього кожна наступна задача коштує в 2-3 рази більше ітерацій.

## Skills, rules, commands

Primary tools дозволяють зберігати reusable інструкції у проєкті. Базовий мінімум — фіксуй повторювані task-types як skills або commands.

### Структура (Cursor)

```
.cursor/
├── rules/           # Завжди активні правила (coding standards, conventions)
│   └── *.mdc
├── skills/          # Завантажуються on demand (per task type)
│   └── <skill-name>/
│       └── SKILL.md
├── commands/        # Slash commands (інженер викликає вручну)
│   └── <command>.md
└── hooks/           # Auto-run scripts (див. далі)
```

### Структура (Claude Code)

```
.claude/
├── skills/
├── commands/
├── agents/
└── settings.json    # Hooks, permissions
CLAUDE.md            # Entry point
```

### Що створити на старті

На першому тижні setup — створюй тільки те, що вже повторив 2+ рази. Не будуй порожню бібліотеку skills "про запас".

Базовий набір, що окупається на типовому проєкті:

- `commands/plan.md` — slash-команда генерації плану за лінком на Jira/issue.
- `commands/review.md` — ре-прогін diff через незалежну модель.
- `commands/verify.md` — запуск lint/type-check/test локально + аналіз результату.
- `skills/write-test.md` — як писати тести у стилі цього проєкту (з посиланнями на реальні приклади).

> 💡 **Hint:** Skill працює якісно тільки якщо в кодовій базі є reference-приклади, на які він може спиратися. Якщо таких прикладів немає — спочатку стандартизуй 1-2 приклади руками, потім описуй skill. Зворотний порядок генерує nonsense.

## MCP-сервери

Model Context Protocol розширює AI доступом до зовнішніх систем (Jira, GitHub, Figma, framework-specific docs). Базовий setup — встанови хоча б один MCP, що закриває реальний pain point проєкту.

### Типовий стартовий набір

| MCP server                 | Коли потрібен                                    | Де встановити             |
| -------------------------- | ------------------------------------------------ | ------------------------- |
| Atlassian / Jira           | Задачі беруться з Jira; авто-заповнення контексту | Cursor / Claude Code / Copilot |
| GitHub                     | Робота з PR/issues через AI                       | Всі primary tools          |
| Figma                      | Верстка за макетами                               | Cursor / Claude Code       |
| Framework-specific (Angular MCP, Blazor/Telerik, MUI) | Проєкт використовує відповідний фреймворк | Primary tool за вибором    |
| Context7 / documentation   | Робота з новими бібліотеками, де AI's pretraining застарів | Всі primary tools |

### Встановлення (Claude Code)

```bash
claude mcp add <name> <command>
```

Приклад для Atlassian:

```bash
claude mcp add atlassian npx -y @atlassian/mcp-server
```

Після додавання — рестарт сесії, перевірка: `/mcp` у Claude Code має показати connected сервер.

### Встановлення (Cursor)

`Settings → MCP → Add Server` → JSON-конфіг:

```json
{
  "mcpServers": {
    "atlassian": {
      "command": "npx",
      "args": ["-y", "@atlassian/mcp-server"],
      "env": {
        "ATLASSIAN_URL": "https://<tenant>.atlassian.net",
        "ATLASSIAN_API_TOKEN": "<from keychain, not plain>"
      }
    }
  }
}
```

API token — через OS keychain або env var, не у plain JSON, який комітиться.

### Framework-specific MCP

Сучасні фреймворки випускають власні MCP-сервери з актуальним LLM-контекстом (best practices, API sigs). Якщо проєкт на Angular 18+, React 19, .NET 9 тощо — перевір офіційний MCP фреймворку перед тим, як "навчати" AI вручну через rules.

Приклад: `npx @angular/mcp` — Angular MCP з вбудованими best practices під LLM.

### Обмеження

- MCP-сервер отримує доступ до облікових записів і даних → перевіряй джерело (official vs community). На client-проєктах — тільки official або approved.
- Кожен додатковий MCP збільшує контекст. Не вмикай "про запас"; вмикай під конкретний workflow.
- Деякі MCP (Figma зокрема) працюють нестабільно на складних макетах — не закладайся, що UI-верстка з Figma MCP буде 100% accurate, перевіряй візуально.

> 💡 **Hint:** MCP — це "ролі" для AI. Jira MCP = робота з задачами. Figma MCP = читання макетів. GitHub MCP = PR/issues. Не плутай MCP з framework-lib: для звичайних npm-залежностей AI і без MCP знає достатньо.

## Допоміжні інструменти

Setup допоміжних tools із розділу 2 — по факту потреби, не "на всякий випадок".

### ChatGPT / Gemini (web)

- Звичайна підписка (Plus / Pro).
- Увімкнути "Do not train on my data" у налаштуваннях акаунту.
- Використовуй для cross-check, brainstorm, швидких питань **не про код клієнта**. Client code — через primary tool із налаштованим privacy mode.

### Ollama / LM Studio (локально)

Потрібні, коли код не може залишати машину (NDA, data residency).

**Встановлення Ollama:**

```bash
# macOS / Linux
curl -fsSL https://ollama.com/install.sh | sh

# Завантажити модель під задачу:
ollama pull qwen2.5-coder:14b        # code generation
ollama pull deepseek-coder-v2         # heavier reasoning
```

**Інтеграція з primary tool:**

- Cursor: `Settings → Models → Add Custom Model → OpenAI-compatible endpoint`, вказати `http://localhost:11434/v1`.
- Claude Code: не підтримує напряму; для local-only роботи використовуй Continue.dev або Cline як окремий tool.

> 💡 **Hint:** Локальна модель — не "безкоштовний варіант" для економії на токенах. Якість нижча, швидкість залежить від GPU. Використовуй лише коли NDA/security вимагає. Для робочих задач cloud-модель швидше, дешевше на підсумку і точніше.

### Voice input (опціонально)

Для довгих plan-сесій голосом замість набору:

- Tool: Spokenly (macOS) або аналог для Windows/Linux.
- Підключається через OpenAI Whisper API (per-token billing, зазвичай $2–5/міс за помірного вжитку).
- Налаштовується під natural mixing мов (UA/EN/RU).

Не обов'язковий компонент setup; додається, коли інженер реально витрачає > 30 хв/день на планування.

## Автоматизація: hooks і permissions

Hook — скрипт, що виконується автоматично після певних tool-event'ів (наприклад, після кожного AI-редагування файлу запустити lint). Це знімає з інженера повторювані перевірки і фіксує quality gates на рівні tool, а не disciplined-memory.

### Мінімальний setup (Claude Code)

`.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "<lint-команда проєкту>", "timeout": 60 },
          { "type": "command", "command": "<type-check-команда проєкту>", "timeout": 60 }
        ]
      }
    ]
  }
}
```

Що це дає: після кожного AI-редагування коду — автоматично прогоняються lint і type-check. Якщо щось ламається, агент бачить помилку у власному output і коригує у тій же сесії.

**Підстав команди свого стеку** — нижче приклади для Node.js-проєктів; для інших стеків (PHP, Java, Python, Go тощо) використовуй відповідний lint/compile-скрипт зі свого `package.json` / `pom.xml` / `pyproject.toml`:

| Менеджер пакетів | lint команда | type-check команда |
| --- | --- | --- |
| pnpm | `pnpm run lint` | `pnpm run type-check` |
| npm | `npm run lint` | `npm run type-check` |
| yarn | `yarn lint` | `yarn type-check` |

> 💡 **Hint:** Якщо у проєкті немає окремого `type-check` скрипту — прибери другий рядок з hooks. Неіснуюча команда у hook-у змусить агента зупинятись з помилкою після кожного edit-у.

### Permissions (Claude Code)

`.claude/settings.local.json`:

```json
{
  "permissions": {
    "allow": [
      "Bash(<lint-команда>:*)",
      "Bash(<type-check-команда>:*)",
      "Bash(<test-команда>:*)"
    ]
  }
}
```

Приклади для Node.js (підстав менеджер пакетів свого проєкту):

```json
// pnpm
"Bash(pnpm run lint:*)", "Bash(pnpm run type-check:*)", "Bash(pnpm test:*)"

// npm
"Bash(npm run lint:*)", "Bash(npm run type-check:*)", "Bash(npm test:*)"

// yarn
"Bash(yarn lint:*)", "Bash(yarn type-check:*)", "Bash(yarn test:*)"
```

Для інших стеків — замінити на відповідні lint/compile/test команди проєкту.

Це whitelist команд, які AI може виконувати без явного approve. Усе, що поза списком, — вимагає ручного підтвердження. `*.local.json` — не комітиться у репозиторій (per-developer).

### Коли додавати hooks

- Коли одну й ту ж команду (`lint`, `type-check`, `test`) інженер запускає після кожного AI-edit-у вручну.
- Коли були прецеденти merge-у "зеленого" коду, що ламав lint/types на CI.

### Коли **НЕ** додавати

- На ранньому етапі setup — до перших 10-20 AI-задач. Без практики незрозуміло, які hooks реально потрібні.
- Якщо команди дорогі за часом (> 60 сек) — сповільнюють цикл Plan→Apply→Review настільки, що AI-agent розгубиться у timeout-ах.

> 💡 **Hint:** Hooks — це level-2 оптимізація, не обов'язкова для старту. Спочатку опануй ручний цикл Plan→Apply→Review з розділу 5. Коли зрозумієш, які саме перевірки ти повторюєш щоразу, — винось їх у hooks.

## Verification: starter exercise

Setup вважається завершеним, тільки якщо інженер пройшов verification exercise на реальному проєкті.

### Ціль

Переконатися, що:

- AI читає `AGENTS.md`/`CLAUDE.md`;
- model routing працює;
- privacy mode увімкнено;
- ignore-файл не пропускає sensitive зон;
- базовий цикл Plan → Apply → Review виконуваний без додаткових troubleshooting'ів.

### Покроково

1. **Відкрий реальний проєкт у primary tool.** Не playground. Не hello-world.
2. **Запусти "What do you know about this project?"** Очікуваний результат — AI відповідає term-ами з `AGENTS.md`/`CLAUDE.md` (architecture, commands, naming conventions). Якщо відповідь generic ("це TypeScript проєкт з React") — entry-point не читається, перевір шлях і формат.
3. **Запитай Plan на мінімальну зміну.** Наприклад: "Plan the addition of a `<Banner>` component under `src/components/banner/`, with props `title: string`, `tone: 'info' | 'warning'`, and a unit test." Очікуваний план повинен посилатися на реальні файли і conventions проєкту (kebab-case, `.component.tsx`, test-patterns тощо).
4. **Apply.** Дозволь AI створити файли. Переглянь diff — чи дотримано naming, import order, стилю проєкту.
5. **Verify.** Запусти `lint`, `type-check`, `test` (або проектний еквівалент). Жодна з команд не повинна fail-ити на AI-згенерованому коді.
6. **Cleanup.** Відкотити зміни (`git checkout .` або видалити створені файли). Verification не комітиться.

### Критерії пройденого verification


| Перевірка                                          | Очікування                                               |
| -------------------------------------------------- | -------------------------------------------------------- |
| AI знає стек і conventions проєкту                 | Так (без prompt-уточнень)                                |
| Plan посилається на реальні файли/директорії        | Так                                                      |
| Згенерований код проходить lint + type-check + tests| Так                                                      |
| Чутливі директорії не потрапили у контекст         | Перевірено: AI не цитує `.env`, `secrets/`, `src/auth/crypto/` |
| Час на весь exercise                               | < 30 хв                                                  |

Якщо хоча б одна перевірка failed — повернися до відповідного підрозділу і перекрий гап перед тим, як переходити до реальних задач проєкту.

> 💡 **Hint:** Якщо не можеш пройти verification на власному проєкті — проблема майже ніколи не в інструменті. Переважно причина: відсутній або слабкий `AGENTS.md`, неувімкнений privacy mode, або не той tier моделі. Не "переустановлюй усе" — перевір ці три речі спочатку.

## Типові проблеми та їх вирішення

Список проблем, що з'являються на setup-етапі найчастіше, і швидкий фікс до кожної.

| Симптом                                                        | Ймовірна причина                                           | Фікс                                                                         |
| -------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------- |
| AI генерує код у чужому стилі проєкту                           | Відсутній або неповний `AGENTS.md`/`CLAUDE.md`              | Створити/розширити entry-point; додати File naming conventions; додати Code style rules |
| AI hallucinate неіснуючі бібліотеки / API                      | Pretraining застарів або AI не має доступу до актуальних docs | Додати framework-specific MCP (Context7, Angular MCP тощо); дати посилання на package.json у промт |
| Токени витрачаються втричі швидше за очікуване                  | Opus використовується там, де достатньо Sonnet; або запущено subagent-orchestration без depth limit | Перевірити model selection у sessions; зафіксувати Sonnet як default; вимкнути subagents поки немає Level 2/3 досвіду |
| Cursor / Claude не бачить файлів проєкту                         | Запущено не з project root; або файли у `.cursorignore`/AI-ignore | `cd <project-root>` перед стартом; переглянути ignore-файл                 |
| Copilot не пропонує suggestions                                  | Ліцензія не активна; Suggestions matching public code=Block блокує типові паттерни | Перевірити `GitHub Settings → Copilot`; тимчасово змінити "Block" на "Allow" і спостерігати |
| Lint/type-check завжди падає після AI-правок                     | AI не знає команд (`pnpm` vs `npm`, custom scripts)         | Додати Quick reference у `AGENTS.md`; додати PostToolUse hook               |
| MCP-сервер статус "disconnected"                                 | ENV vars не встановлено або API token expired              | Перевірити `env` у mcp config; перевидати token                              |
| AI "забуває" raised раніше обмеження у середині сесії            | Контекст переповнений (> 70%)                              | Почати новий chat з відрефакторованим планом у промті                       |

## Документування setup'у на проєкті

Завершений setup — self-documenting. Наступний інженер на проєкті має бути здатний повторити setup без прямої передачі знань.

Мінімум, що додається до `AGENTS.md`:

```markdown
## AI setup

- **Primary tool:** Claude Code (CLI + JetBrains plugin) / Cursor Pro / Copilot Business.
- **Default model:** Claude Sonnet. Opus — вручну на планування, multi-file refactor, architecture. Для Claude Code — [`"model": "opusplan"`](#claude-code) автоматизує це.
- **MCP enabled:** Atlassian (Jira), GitHub, Context7.
- **Hooks:** PostToolUse → `pnpm lint && pnpm type-check`.
- **Sensitive zones** (AI disabled): `src/auth/crypto/`, `src/billing/`.
- **Approved supporting tools:** ChatGPT Pro (no client code), NotebookLM (docs only).
- **Restrictions (per client contract):** <посилання на clause / None>.
```

Якщо проєкт під NDA з особливими обмеженнями — ці обмеження фіксуються explicitly, не у Slack-історії.

> 💡 **Hint:** Якщо на проєкті 2+ інженери — однакова `AI setup` секція у всіх == половина консистентності команди. Друга половина — однакові skills/rules у `.cursor` / `.claude`. Комітьте ці директорії у репозиторій; різницю per-developer тримайте у `*.local.json`.

## Чек-лист готовності до розділу 4 (Context Engineering)

Перед переходом до поглибленої роботи з контекстом інженер має могти відповісти "так" на всі пункти:

- Primary tool встановлений, оновлений, авторизований.
- Privacy mode / no-train увімкнено; telemetry вимкнено.
- Model routing зафіксовано: Opus для планування і складних змін, Sonnet як default для виконання. Для Claude Code — `"model": "opusplan"` автоматизує це.
- `AGENTS.md` / `CLAUDE.md` існує у корені проєкту і містить Quick reference, Architecture overview, File naming, Code style rules, AI setup.
- `.cursorignore` / AI-ignore налаштовано; sensitive зони виключені.
- Хоча б один MCP-сервер релевантний проєкту налаштовано і працює (`/mcp` = connected).
- Verification exercise пройдено на реальному проєкті за < 30 хв.
- AI setup секція у `AGENTS.md` заповнена; наступний інженер зможе повторити setup по документу.

Якщо хоча б на один пункт відповідь "ні" — повернися до відповідного підрозділу перед рухом далі. Розділ 4 (Context Engineering) будує поверх цього базового setup і припускає його наявність як даність.
